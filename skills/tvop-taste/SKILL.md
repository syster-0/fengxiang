# tvop-taste · 去 AI 味打分与回炉

## 何时使用

- 写完一条评论，要确认它像不像真人写的。
- 用户说「读起来像 AI」「太模板了」「一眼假」。
- 要查规则表：哪些是 AI 味特征、哪些不算。

采集走 `$tvop-crawl`；落库走 `$tvop-okf`。本 skill 只管**打分与回炉**。

## 核心立场

**人味是准入因子，不是加分项。**

体系里 `humanness` 出现在排序分的**乘数位**：
```
rank = weight × (0.5 + 0.5·humanness) × (1 + 0.4·resonance) × (1 + 0.2·tension) × penalty
```
即：AI 味重的内容，权重再高也被乘下去。**门槛 0.60 是硬门，不达标的 concept 不能标 verified。**

反过来说 —— **不许为了过门调数字。** 打分器只是尺子，改尺子等于自毁体系。
不达标就回炉改写。

## 常用命令

```bash
tvop taste score --file <文件>            # 打分（详细）
tvop taste score --file <文件> --quiet    # 只输出人味分（脚本用）
tvop taste score --file <文件> --json
tvop taste rules                          # 11 条算子 + 15 项非判别 + 增强项
echo "文本" | xargs -0 tvop taste score   # 直接给文本
```

## 11 条人味算子（命中即回炉）

| # | 算子 | 改法 |
|---|---|---|
| 1 | 翻案腔 | 「其实…并不是…而是…」这类反转句式，直接写结论 |
| 2 | 顿号罗列过密 | 能概括就别逐项列举；必须三项以上就改其中一项的句法 |
| 3 | 相邻句结构同款 | 打散其中一句：合并、拆分、换语序 |
| 4 | 破折号滥用 | 直接写完整句子，或改用逗号句号 |
| 5 | 冒号滥用 | 提示语不承担信息就删掉，承担衔接就换句号 |
| 6 | 序数词标题 | 「首先/其次/最后」改成内容自带顺序 |
| 7 | 拟人化喻体 | 一条以内；两条以上是模仿秀 |
| 8 | 概括盖数据 | 把「表现出色」换回具体的型号、数字、条件 |
| 9 | 禁用起手式 | 删掉「众所周知」「不难发现」「值得注意的是」 |
| 10 | 翻译腔五种 | 「进行了一个…的动作」类，改回中文动词 |
| 11 | 段首零回指 | 段首补一个指向上文的具体词，别用抽象总起 |

## 15 项**不构成**改写理由的特征

这些是 AI 与人类**共有**的写法，命中不代表要改：
—— 不要因为它们就把句子改得不像人。

排序上，**只有 11 条算子越界才回炉。**

## 7 项人味增强项（只观测，不构成改写理由）

正文设问 / 比喻标记 / 口语连接词 / 单字虚词（就、很、了、吧、啊、呢、嘛）/
具体数字密度 / ……

这些指标**偏低**时会提示「生成时应刻意补足」，但**不得据此删改既有文本**。
方向是单向的：**只在写新的时补，不在改旧的时加。**

## 回炉流程（不达标时）

1. 看 `--json` 的 `hits`，按 `excess`（超基线程度）从高到低排。
2. **只改命中项，不动其他句子。** 一次改一处，改完重打分。
3. 常见对症：
   - 破折号多 → 改逗号或独立句（本领域最常踩，因为爱用「——」做补充）；
   - 顿号罗列 → 概括、或把第三项换个句法；
   - 概括盖数据 → 补型号/尺寸/口径；
   - 相邻句同款 → 拆一句。
4. 改到 ≥ 0.60。**若改了几轮仍上不去，问题通常在结构（比如整篇是分点清单），
   那就换声部或换骨架，而不是继续磨句子。**

## 声部与目标张力

打分要合声部看：`douyin-conflict` 目标张力 0.85，句子本来就该短促、判决前置；
不能拿 `zhihu-rational` 的标准去要求它。**张力是参数，不是优劣。**

## 输出规范

- 报：人味分、AI 味分、字数/段数/句数、门槛是否通过。
- 报：命中的算子（按超出程度排序）+ 每条的改法 + 原文片段。
- 回炉后报**前后对比**，让用户看到改了哪里、涨了多少。
- 人味增强项建议只在**生成新内容**时给；改写既有文本时不要拿它当理由。
